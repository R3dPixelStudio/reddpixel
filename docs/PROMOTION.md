# REDDPIXEL daily promotion checklist

Goal: qualified conversations about creative digital work. The blog explains real builds; Superintelliget shows experiments and personality. Electrical media supports the technical identity, rather than advertising worldwide field services. Nothing has been posted or sent automatically.

## Set up once

- [ ] Review the first article at `/blog/portfolio-content-before-webgl/`, confirm public facts, then deploy.
- [ ] Add `https://reddpixel.com/?utm_source=instagram&utm_medium=social&utm_campaign=profile#work` to @SUPERINTELLIGET's bio. Suggested line: “Creative coding & visual experiments. My work → REDDPIXEL.”
- [ ] Add the portfolio to LinkedIn's website/Featured section. Pin an original build explanation and a portfolio introduction.
- [ ] Check the Instagram link on a phone: `https://www.instagram.com/superintelliget/`.
- [ ] When YouTube launches, add the exact channel URL to `PROFILE.youtube` and rebuild. Contact links then include it automatically.
- [ ] Complete the Search Console and Bing checklist in SEO.md. Submit the generated sitemap containing the homepage, blog and first article.
- [ ] Keep a private log: date, content URL, topic, channel, useful replies, qualified inquiries and follow-up date. Record when someone mentions a specific post.
- [ ] Collect original website recordings, clean renders and electrical photos/timelapses. Check permission to show site/client details; remove private names, addresses and access details.

## Every day: 35–45 minutes

- [ ] **5 minutes: capture proof.** Save one original screenshot, recording or process photo. Note the problem, decision and change. Use real device measurements when discussing performance.
- [ ] **10 minutes: reply.** Respond to relevant comments and existing inquiries. Ask about the goal, audience, deliverable and timeline.
- [ ] **10 minutes: join one useful conversation.** Leave a specific observation on a relevant studio/developer/client post. Share a related example only when useful. Avoid copied comments, mass messages and generic pitches.
- [ ] **8–18 minutes: advance this week's piece.** Follow the weekly loop. Daily progress does not require daily publishing.
- [ ] **2 minutes: log what mattered.** Save useful questions and qualified inquiries. Repeated questions become future project notes.

## Weekly loop

| Day | Task | Deliverable |
| --- | --- | --- |
| Monday | Pick an actual project problem or engineering decision and who needs to understand it. | One useful question and an original clip. |
| Tuesday | Draft a useful explanation: problem, constraints, approach, evidence and limits. | Saved draft in `/admin/`; repository content remains an alternative. |
| Wednesday | Review facts/code and preview the saved draft on mobile. Publish when ready; code changes also require build/lint/SEO checks. | One substantive article; every other week is fine. |
| Thursday | Adapt that work into an Instagram Reel/carousel and a short LinkedIn explanation. Link the specific article. | One or two useful posts. |
| Friday | Show a visual breakdown or electrical process footage. Explain the technical decision simply. | A short original process post. |
| Saturday | Review search data and inquiries for 15–20 minutes. | One improvement based on actual queries or questions. |
| Sunday | Rest or batch-capture next week's clips. | A sustainable next step. |

When busy, prioritize the real build and useful replies. A strong note every two weeks beats invented filler. YouTube can reuse your own footage once launched; adapt its pacing and captions.

## Article queue

1. **Implemented:** “The portfolio should load before the cube”: readable HTML, scene readiness, failure paths and paused rendering.
2. **After mobile testing:** What changes between the mobile and desktop cube, with actual device results.
3. **After selecting artwork:** A procedural visual breakdown with source stages and your contribution.
4. **After adding footage:** An electrical process story about planning, constraints and documentation. Use it as project evidence, not an unsafe installation tutorial.
5. **After gathering evidence:** A website case study with the brief, role, constraints, screenshots and real outcomes. No invented metrics.

## Before each publication

- [ ] Shows work you actually did and explains a useful decision.
- [ ] Public facts and media permissions checked.
- [ ] Readable on a phone, with descriptive image alternatives.
- [ ] Title, description, canonical, visible content and destination agree.
- [ ] Natural link back to relevant work/contact.
- [ ] Adds something beyond a generic AI summary or keyword list.

This cadence is a working plan, not a ranking promise.
